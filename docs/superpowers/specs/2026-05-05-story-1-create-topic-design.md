# Story 1: Create a Topic Manually — Design Spec

**Date:** 2026-05-05
**Story:** Story 1 from `docs/user-stories.md`
**Scope:** Story 1 only — thin end-to-end slice. No auth, no edit/delete, no AI.

## Acceptance Criteria (from user story)

1. Capture title, summary, and an initial guidance text.
2. Record who created the topic.
3. The new topic appears in the topic list.

---

## Database Schema

Two tables added to `src/db/schema.ts`. Both use `uuid` primary keys (default `gen_random_uuid()`) and `timestamptz` for all time columns.

### `topics`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default gen_random_uuid() |
| `title` | text | NOT NULL |
| `summary` | text | NOT NULL |
| `createdBy` | text | NOT NULL — free-text name, placeholder for future auth |
| `createdAt` | timestamptz | NOT NULL, default now() |
| `currentVersionId` | uuid | NULL, FK → topic_versions.id |

### `topic_versions`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | PK, default gen_random_uuid() |
| `topicId` | uuid | NOT NULL, FK → topics.id ON DELETE CASCADE |
| `guidanceText` | text | NOT NULL |
| `createdBy` | text | NOT NULL |
| `createdAt` | timestamptz | NOT NULL, default now() |

**Schema decisions:**

- `currentVersionId` is nullable because at insert time no version exists yet. It is populated in the same transaction that creates the first version.
- `createdBy` exists on both tables intentionally: the topic-level field records "who started this subject"; the version-level field records "who authored this particular guidance text." These will diverge once approvers (Story 17) can differ from original authors.
- `ON DELETE CASCADE` on `topicId` FK: deleting a topic deletes its versions.
- The `currentVersionId` FK approach (pointer on `topics`) prevents the "two rows both marked current" bug that a `isCurrent boolean` column on `topic_versions` allows.

**Migration:** generated by `npx drizzle-kit generate`, applied with `npx drizzle-kit migrate`. Both `schema.ts` and the generated SQL file are committed.

## Validation Rules (Zod — `src/app/topics/new/schema.ts`)

```ts
createTopicSchema = z.object({
  title:        z.string().trim().min(3).max(120),
  summary:      z.string().trim().min(10).max(400),
  guidanceText: z.string().trim().min(10).max(10_000),
  createdBy:    z.string().trim().min(1).max(120),
})
```

- `.trim()` runs **before** `.min()` so whitespace-only submissions are rejected.
- All fields are required; none are optional.
- HTML `required` + `maxLength` attributes on inputs provide UX hints but are not trusted by the server.

## Server Action Flow (`src/app/topics/new/actions.ts`)

```
1. Extract raw values from FormData (title, summary, guidanceText, createdBy)
2. Parse with createTopicSchema.safeParse(...)
   → if fails: return { fieldErrors, values } — form re-renders with errors + preserved input
3. Open db.transaction:
   a. INSERT INTO topics (title, summary, createdBy) RETURNING id
   b. INSERT INTO topic_versions (topicId, guidanceText, createdBy) RETURNING id
   c. UPDATE topics SET currentVersionId = version.id WHERE id = topic.id
4. revalidatePath('/topics')   // invalidate cached list BEFORE redirect
5. redirect(`/topics/${topicId}`)
```

**Error handling:**

| Scenario | Behavior |
|---|---|
| Validation fails | Return `{ fieldErrors, values }` — inline errors, preserved input |
| DB unavailable | Transaction throws; surfaces as 500 / Next error boundary |
| Redirect target missing | Impossible — redirect uses the id from the just-committed insert |

DB errors are not caught and pretty-printed; they surface honestly.

**`useActionState` contract:** the Server Action signature is `(prev: FormState, formData: FormData) => Promise<FormState>`. The `prev` parameter is ignored; every submission re-validates from scratch.

## List Page (`src/app/topics/page.tsx`)

- Server Component; no client state.
- Query: `db.select(...).from(topics).leftJoin(topicVersions, eq(topics.currentVersionId, topicVersions.id))` ordered by `topics.createdAt desc`.
- Uses `leftJoin` (not `innerJoin`) so a topic temporarily lacking `currentVersionId` appears rather than being silently hidden.
- Empty state: "No topics yet. Create the first one." with a link to `/topics/new`.
- Each row: topic title as a link to `/topics/[id]`, summary text below.

---

## Detail Page (`src/app/topics/[id]/page.tsx`)

- Server Component; no client state.
- Query: `db.select(...).from(topics).innerJoin(topicVersions, eq(topics.currentVersionId, topicVersions.id)).where(eq(topics.id, params.id))`.
- If query returns no rows: `notFound()` → renders `not-found.tsx`.
- Displays: title, `createdBy · createdAt` (formatted `en-GB` long date via `Intl.DateTimeFormat`), summary, guidance text.
- `guidanceText` rendered with `whitespace-pre-line` CSS to preserve author line breaks without requiring Markdown.

---

## Form Page (`src/app/topics/new/`)

- `page.tsx` is a Server Component that imports `<TopicForm>` (Client Component).
- `TopicForm` holds `useActionState(createTopic, {})` and renders `<form action={formAction}>`.
- Four inputs: title (`<input>`), summary (`<textarea>`), guidanceText (`<textarea>`), createdBy (`<input>`).
- Inline field errors rendered below each input from `state.fieldErrors`.
- Input values repopulated from `state.values` after failed submission.

## Testing Strategy

**Framework:** Playwright (`@playwright/test`). Added to `devDependencies`; `npm run test:e2e` → `playwright test`.

**Config (`playwright.config.ts`):** `baseURL: 'http://localhost:3000'`, `webServer` pointing at `npm run dev` with `reuseExistingServer: true`.

**Database:** tests run against the dev Docker Postgres (port 15432). Test data is left in place after runs; no cleanup in Story 1.

**Specs (`e2e/create-topic.spec.ts`):**

1. **Happy path** — fill all fields, submit, assert redirect to detail page showing all entered data, navigate to list and assert topic appears with title + summary.
2. **Validation errors** — submit empty form, assert error messages visible, assert still on `/topics/new`.
3. **Value preservation** — fill title only, submit, assert title input still holds typed value.
